🏗️ Visión General del Framework

HarmBench establece tres propiedades clave para evaluaciones de red teaming: amplitud (broad behaviors), comparabilidad (parámetros estandarizados), y métricas robustas (classificadores resistentes al gaming). A diferencia de evaluations previas que usaban menos de 100 behaviors, HarmBench contiene 510 comportamientos únicos diseñados para violar leyes o normas.

🧩 4 Categorías Funcionales

Las categorías funcionales describen propiedades únicas de los behaviors que permiten medir diferentes aspectos de la robustez de un LLM.

📝 Standard Behaviors
Basados en datasets existentes (AdvBench, TDC 2023). Strings de behavior auto-contenidos sin contexto adicional.
200 behaviors
📚 Copyright Behaviors
Piden al modelo generar contenido protegido. Clasificador basado en hashing para detectar reproducción literal.
100 behaviors
🔗 Contextual Behaviors
Incluyen un string de contexto + behavior. Evaluaciones más realistas y diferencialmente dañinas. 0% searchability vs 50% en datasets previos.
100 behaviors
🖼️ Multimodal Behaviors
Incluyen imagen + behavior. Evalúan LLMs multimodales contra ataques que aprovechan inputs visuales.
110 behaviors

⚔️ 18 Métodos de Ataque

HarmBench evalúa 18 métodos de red teaming de 12 papers, categorizados por tipo de acceso y modalidad. Los métodos textuales incluyen white-box, black-box y transfer attacks.

# Método Tipo Categoría Descripción
1 GCG White-box Optimización Greedy Coordinate Gradient — optimiza sufijos adversariales usando gradientes. El más efectivo contra modelos robustos.
2 GCG (Multi) Multi-turn Optimización Variante multi-turn de GCG que distribuye el ataque across múltiples turnos de conversación.
3 GCG (Transfer) Transfer Optimización Optimiza contra un modelo surrogate y transfiere el ataque al modelo target.
4 PEZ White-box Optimización Projected Gradient Descent en espacio de embeddings para generar ataques en espacio continuo.
5 GBDA White-box Optimización Gumbel-Softmax Black-box Differentiable Attack — optimización diferenciable con Gumbel-Softmax.
6 UAT White-box Optimización Universal Adversarial Triggers — triggers universales que funcionan across múltiples inputs.
7 AutoPrompt White-box Optimización Greedy search para encontrar tokens adversariales óptimos automáticamente.
8 Stochastic Few-Shot Black-box LLM Optimizer Genera ejemplos few-shot estocásticamente usando un LLM como optimizador.
9 Zero-Shot Black-box Template Usa templates predefinidos sin optimización. Baseline de jailbreaks manuales.
10 PAIR Black-box LLM Optimizer Prompt Automatic Iterative Refinement — un LLM genera y refina jailbreaks iterativamente. ~20 queries.
11 TAP Black-box LLM Optimizer Tree of Attacks with Pruning — búsqueda en árbol con poda para encontrar jailbreaks óptimos.
12 TAP (Transfer) Transfer LLM Optimizer TAP optimizado para transferibilidad entre modelos.
13 AutoDAN Black-box Genetic Algoritmo genético para generar jailbreaks que suenan naturales y evitan detección.
14 PAP Black-box LLM Optimizer Prefix Automatic Prompting — optimiza prefijos para maximizar la probabilidad de jailbreak.
15 Human Jailbreaks Humano Baseline Jailbreaks diseñados por humanos. Baseline que representa la creatividad humana.
16 Direct Request Baseline Baseline Peticiones directas sin optimización. Mide la tasa base de compliance del modelo.
17 PGD Vision Multimodal Projected Gradient Descent para imágenes adversariales en LLMs multimodales.
18 Adversarial Patch Vision Multimodal Parche visual adversarial que controla el comportamiento del modelo en runtime.

🔄 Pipeline de Evaluación

01
Generación de Test Cases
El método de red teaming g recibe behaviors {y₁, y₂, ..., yₘ} y genera test cases {x₁, x₂, ..., xₙ} para cada behavior. Parámetro estandarizado: N=512 tokens para greedy decoding.
02
Generación de Completions
Los test cases se pasan al LLM target f, que genera T tokens con greedy decoding (determinístico) para producir outputs fT(xi) = x'i.
03
Evaluación con Clasificador
Las completions se evalúan usando un clasificador c fine-tuned (Llama 2 13B Chat) que determina si el modelo exhibió el comportamiento. ASR = (1/N) Σ c(fT(xi), y).
Métrica ASR // Attack Success Rate — métrica principal ASR(y, g, f) = (1/N) × Σ c(fT(xi), y) // dnde: // y = comportamiento objetivo // g = método de red teaming // f = modelo target // c = clasificador (Llama 2 13B fine-tuned) // N = 512 tokens (estandarizado)

🛡️ R2D2 — Adversarial Training para Robust Refusal

Robust Refusal Dynamic Defense (R2D2) — método novel de adversarial training que fine-tunea LLMs usando un pool dinámico de test cases continuamente actualizados por GCG. Resulta en el SOTA de robustez contra GCG entre model-level defenses.

Loss Functions // Away Loss — opone al GCG loss ℒaway = -1 × log(1 - fθ(ti | xi)) // Toward Loss — entrena refusal ℒtoward = -1 × log(fθ(trefusal | xi)) // Combined Loss ℒtotal = ℒaway + ℒtoward + ℒSFT
Hiperparámetros // Setup de entrenamiento (Mistral 7B) M = 500 // iteraciones N = 180 // test cases persistentes m = 5 // GCG steps por iteración n = 8 // test cases actualizados K = 20% // reset de pool cada L=50 // Tiempo: 16 horas en 8×A100

📊 Resultados de Robustez (ASR ↓)

Zephyr 7B (sin R2D2) Alto
Llama 2 7B Chat 31.8% ASR
Llama 2 13B Chat 30.2% ASR
Zephyr 7B + R2D2 5.9% ASR ✦ SOTA

Resultado clave: Zephyr 7B + R2D2 reduce el ASR de GCG en 4× comparado con Llama 2 13B (el segundo más robusto). MT-Bench score se mantiene en 6.0/6.5 — la utilidad general se preserva.

💡 Hallazgos Clave

🔄 Ningún ataque o defensa es uniformemente efectivo
Todos los ataques tienen ASR bajo en al menos un LLM, y todos los LLMs tienen robustez pobre contra al menos un ataque. Entrenar contra un solo ataque no garantiza robustez general.
📏 La robustez es independiente del tamaño del modelo
No hay correlación entre robustez y tamaño del modelo dentro de familias. Los datos de entrenamiento y algoritmos son mucho más importantes que el tamaño (7B-70B evaluados).
🔗 Contextual behaviors son más difíciles
El ASR es considerablemente más alto en contextual behaviors a pesar de su mayor potencial de daño diferencial. Los filtros existentes no capturan bien el contexto.
⚡ GCG es el ataque más efectivo en modelos robustos
GCG obtiene el ASR más alto en modelos como Llama 2 que tienen mecanismos de refusal fuertes. Los ataques black-box son menos efectivos contra estos modelos.
🖼️ Ataques multimodales son más fuertes
PGD-based attacks en LLMs multimodales obtienen ASR relativamente alto. Render Text baseline es bajo, confirmando que los ataques de imagen son más peligrosos.
🎯 Entrenamiento adversarial preserva utilidad
R2D2 mejora robustez significativamente mientras preserva el rendimiento general (MT-Bench 6.0 vs 6.5 de Mistral base). No hay trade-off drástico.
